# Google OAuth operations

## Canonical configuration

The production customer-auth origin is `https://sim.africa`. Keep these three
settings aligned:

| Setting | Production value |
| --- | --- |
| `NEXTAUTH_URL` | `https://sim.africa` |
| `NEXT_PUBLIC_APP_URL` | `https://sim.africa` |
| Google authorized redirect URI | `https://sim.africa/api/auth/callback/google` |

`NEXTAUTH_URL` is server-side configuration used by NextAuth to construct the
OAuth callback. `NEXT_PUBLIC_APP_URL` is used elsewhere by SIM.Africa for public
payment, order, and webhook URLs. Set both explicitly in the production
deployment rather than relying on deployment-preview host headers.

## Google Cloud configuration

In Google Cloud Console, open **APIs & Services > Credentials**, select the
OAuth 2.0 Client ID used by `GOOGLE_CLIENT_ID`, and ensure its application type
is **Web application**. Add these exact values:

### Authorized JavaScript origins

- `https://sim.africa`
- `http://localhost:3000` (only when local Google sign-in is needed)

### Authorized redirect URIs

- `https://sim.africa/api/auth/callback/google`
- `http://localhost:3000/api/auth/callback/google` (only when local Google
  sign-in is needed)

Do not add a trailing slash to either callback. Save the OAuth client and allow
a few minutes for Google's configuration to propagate.

## Deployment checklist

1. Set `NEXTAUTH_URL=https://sim.africa` and
   `NEXT_PUBLIC_APP_URL=https://sim.africa` in the production environment.
2. Confirm `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` come from the same
   Google OAuth Web client that contains the production redirect URI.
3. Redeploy after changing environment variables.
4. Open `https://sim.africa/api/auth/providers` and confirm the `google`
   provider is present.
5. Start a private-browser sign-in from `https://sim.africa/auth/signin` and
   verify that Google receives
   `redirect_uri=https://sim.africa/api/auth/callback/google`.

An `Error 400: redirect_uri_mismatch` page is generated by Google before the
callback reaches SIM.Africa. Application logs will therefore show no callback
request for this failure; correct the authorized redirect URI on the OAuth
client rather than changing the NextAuth callback route.
